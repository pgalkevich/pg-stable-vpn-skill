Независимые VPN-пути.
Проверяемый маршрут.

Агент настраивает VPN на Keenetic или ASUS с Entware: полный профиль из трёх транспортов, Hysteria2 + AmneziaWG либо рабочий ASUS только с VLESS. Приёмка проверяет реальный трафик, отказ выбранного пути и восстановление.

01

Идея

Один протокол — одна точка отказа

Один туннель может быть быстрым и стабильным сегодня, а завтра перестать работать из-за фильтрации UDP, изменения TLS-handshake, ошибки клиента или деградации конкретного маршрута. Перенастройка одного и того же протокола не создаёт настоящего резерва.

Полный профиль строит три технически разных пути и сохраняет их независимость. Агент меняет по одному транспорту, создаёт rollback anchors и не объявляет успех по статусу RUNNING в панели.

Разные сетиUDP + TCP

Отказ одного класса трафика не выключает всю схему.

Разные клиентыNative + Xray + Kernel

Ошибка одной реализации не распространяется на остальные.

Проверяемый резервHealth check + failover

Маршрут считается живым только после реального запроса.

Основной сценарий

Ubuntu VPS работает публичным сервером, Keenetic или ASUS — клиентом и маршрутизатором. В скиле также есть процедуры для Keenetic в роли публичного VPN-сервера.

ASUS Merlin / GNUton

sing-box обеспечивает TPROXY и защищённый DNS. По явному выбору доступны Hysteria2 + userspace AmneziaWG без Xray или рабочий VLESS-only через официальный Xray. Инструкция ASUS.

Рабочий профиль: один точный российский IPv4

Весь интернет-трафик LAN идёт через согласованный домашний сервер или российский VPS. Каждый путь проверяется по точному IP, DNS защищён VPN, IPv6 проверяется или отключается. При отказе VPN интернет и публичный DNS блокируются. YouTube в эту приёмку не входит. Матрица проверок.

До запуска

Что понадобится

SERVER

Ubuntu VPS

  • Публичный IPv4
  • Ubuntu 24.04 LTS
  • root или полный sudo
  • Рабочие DNS и время
ROUTER

Keenetic / ASUS

  • USB и поддержка OPKG
  • Entware в /opt
  • SSH-доступ root
  • Резервная копия
CONTROL

Компьютер

  • Codex или OpenCode
  • Доступ к двум SSH-хостам
  • Временный SSH-ключ
  • Отдельное LAN-устройство
Компоненты установит агент

3x-ui, AWG Manager, HydraRoute, Xray, Hysteria и туннельные профили установит агент. Набор зависит от платформы: AWG Manager и HydraRoute используются только на Keenetic. До запуска нужен рабочий Entware на роутере.

04

Подготовка Keenetic

Четыре шага до передачи работы агенту

Если у тебя ASUS

Включи custom JFFS scripts и SSH только из LAN, подготовь выделенный USB с ext4 и установи Entware через amtm. Проверь root SSH и /opt после перезагрузки. Следующие четыре шага относятся к Keenetic; для ASUS используй отдельную инструкцию.

1

Добавьте компоненты KeeneticOS

Откройте «Параметры системы → Изменить набор компонентов».

  • Файловая система Ext и утилиты для Ext
  • Поддержка открытых пакетов — OPKG
  • DNS-over-TLS и DNS-over-HTTPS
  • Доступные WireGuard, Netfilter/Xtables и Ping Check
2

Подготовьте USB-накопитель

Выделенный накопитель отформатируйте в EXT4 средствами Keenetic.

Форматирование удалит данные

До начала сохраните всё нужное с выбранного раздела.

3

Определите архитектуру и установите Entware

Установщик должен точно соответствовать процессору роутера.

В Web CLI введите opkg disk, нажмите Tab и выберите накопитель, имя которого начинается с EXT4.

Mipsopkg disk <накопитель> https://bin.entware.net/mipssf-k3.4/installer/mips-installer.tar.gz
Mipselopkg disk <накопитель> https://bin.entware.net/mipselsf-k3.4/installer/mipsel-installer.tar.gz
Aarch64opkg disk <накопитель> https://bin.entware.net/aarch64-k3.10/installer/aarch64-installer.tar.gz
4

Проверьте SSH и /opt

Порт Entware SSH указан в системном журнале.

router shell
ssh root@192.168.1.1 -p 222
passwd
mount | grep ' /opt '
opkg update

Адрес и порт в примере замените своими. Если установщик выдал стандартный пароль, смените его до передачи доступа агенту.

Сначала чек-лист. Затем развёртывание.

Команда init только показывает предварительные условия. Она не подключается по SSH, не запрашивает секреты и ничего не меняет.

04Поэтапная установка

Один транспорт за раз, без одновременной потери всех путей.

Доступы

Укажи тип роутера и выбранный профиль; для рабочего выхода — точный российский IPv4 сервера. Передавайте путь к временному приватному SSH-ключу, а не его содержимое. После завершения отзовите ключ или временный пароль.

07

Приёмка

RUNNING ещё не значит «работает»

Агент завершает установку только после прохождения измеримых проверок.

CONFIG

Конфигурации парсятся, сервисы поднимаются после restart/reboot.

TRAFFIC

Нейтральный HTTPS проходит через каждый выбранный путь; проверяются нужные приложения.

LOAD

Контрольная загрузка не увеличивает UDP drops и RcvbufErrors.

SOAK

Пять–тридцать минут работы без таймаутов и ложного состояния «up».

FAILOVER

В профиле с резервом отказ основного пути переводит трафик на следующий транспорт.

EXIT / DNS

В рабочем профиле IP точно совпадает; при отказе всех путей интернет и публичный DNS заблокированы.

RECOVERY

После возврата сервиса маршрут восстанавливается без ручного ремонта.

LAN
Финальная проверка — с отдельного устройства

Ноутбук или телефон должен быть подключён к LAN роутера без локального VPN. Иначе тест покажет работу постороннего туннеля, маршрута через роутер.

08

Эксплуатация

Что решение гарантирует — и чего не обещает

Да

Независимые пути, воспроизводимая установка, failover, rollback и диагностика по фактам.

Нет

Вечной устойчивости к новым методам фильтрации и совместимости с любой моделью роутера.

Параметры, работающие у одного провайдера, могут вести себя иначе в другой сети. Скил сначала собирает измерения и только затем меняет MTU, fingerprint, маскировку или интервалы смены портов.
